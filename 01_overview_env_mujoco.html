1. 패키지 소개와 커리큘럼

핵심 개념

물리 엔진은 MuJoCo, 로봇 소프트웨어는 ROS 2로 나눈 주행형 양팔 로봇 시스템이다. 주행(Nav2), 양팔 Manipulation(MoveIt), 카메라(Python 직접 수신), LLM 연결까지 전체 파이프라인이 하나의 워크스페이스에 들어 있다.

무대는 로보월드 2026 핑크랩 부스(KINTEX 3홀 A03, 9 × 6 m)다. 로봇이 손님에게 컵을 가져다 드리고 부스를 안내한다.

전체 파이프라인

자연어 지령→LLM→Task Planning→ROS 2→Nav2 / MoveIt→MuJoCo→로봇 행동

수업 형식과 목표

각 모듈은 ros2 launch 또는 스크립트 명령 하나로 실행하며, 아래 순서로 진행한다.

설치 흐름

① ROS 2 Jazzy + 추가 패키지→② 저장소 받기→③ 설치 스크립트→④ OpenAI 키→⑤ 설치 확인

실습 명령

① 공식 안내(ROS 2 Jazzy Ubuntu 설치)대로 ros-jazzy-desktop을 설치한 뒤 git과 한글 글꼴(부스 벽 그래픽의 한글에 필요)을 설치한다. Nav2 · MoveIt · SLAM 등 추가 apt 패키지 24개와 rosdep init/update는 ③ 설치 스크립트가 처리한다.

sudo apt install git fonts-nanum

② → ③ 저장소를 받고 설치 스크립트를 실행한다.

cd ~
git clone https://github.com/PinkWink/pinklab_robotworld2026.git
cd pinklab_robotworld2026
./scripts/install.sh                # 빠진 apt 패키지가 있으면 sudo 비밀번호를 묻는다
./scripts/robotworld doctor     # 환경 점검
apt 패키지→rosdep→가상환경→pip→충돌 검사→.env→colcon build

마지막에 "설치 완료"가 출력되면 성공이다.

# 수업 수강생: 수업에서 받은 키 파일을 .env 로 복사

# 수업 밖에서 따라 하는 경우: 본인 키를 직접 발급해 붙여넣기

⑤ 설치 확인

cd ~/pinklab_robotworld2026
./scripts/robotworld doctor          # 약 10초

doctor는 OS · CPU · RAM · 디스크, apt 패키지, venv · Python 패키지 버전, 빌드, MuJoCo 렌더링 속도, OpenAI 키를 ✅/⚠️/❌로 표시하고 결과를 artifacts/doctor_report.txt에도 저장한다.

ros2 명령을 직접 칠 때 (env.sh)

새 터미널은 ROS 2를 모르는 상태로 열린다. 그래서 아래 세 겹의 환경을 활성화해야 하고, source는 그 터미널 하나에만 적용된다.

source /opt/ros/jazzy/setup.bash             # ① ROS 2 본체: ros2 명령 · 기본 패키지
source .venv/bin/activate                    # ② Python 가상환경: mujoco 등
source install/local_setup.bash              # ③ 내 워크스페이스: 직접 빌드한 패키지

이 과정은 세 줄과 통신 설정을 한 줄로 묶는다.

cd ~/pinklab_robotworld2026
source scripts/env.sh      # ROS 2 Jazzy · venv 가 꺼져 있으면 자동으로 켠다 (bash · zsh)

env.sh 설정 항목은 가상환경 + install 환경 + ROS_DOMAIN_ID=44 + CycloneDDS(localhost)이다. localhost 통신 · 도메인 44라서 강좌 저장소(도메인 43)와 한 PC에서 같이 켜도 토픽이 섞이지 않는다.

확인 포인트

./scripts/robotworld doctor 결과에 ❌ 0건이면 준비 완료다.
  • install.sh는 여러 번 실행해도 안전하다. 네트워크 끊김 등으로 멈추면 다시 실행한다. conda base가 켜진 터미널도 가능하다(venv는 항상 시스템 Python으로 생성).
  • 충돌 검사의 WARN은 무시(이 저장소와 무관한 apt 패키지끼리의 충돌), ERROR는 requirements.txt의 고정 버전을 확인한다.
  • 고정 버전 numpy<2, opencv-python<4.11, setuptools<80 업그레이드 금지 (ROS Jazzy · colcon 호환).
  • 키는 .env의 OPENAI_API_KEY=에만 넣고 저장소에 커밋하지 않는다. 수업 배포 키(temp.env)는 수업 밖 사용과 외부 공유 금지다.
  • 키는 LLM 모듈부터 필요하다. 주행 · MoveIt · Pick & Place 모듈은 키 없이 동작한다. ChatGPT 유료 구독과 API 크레딧은 별개이며 이 과정의 호출량은 수 달러 수준이다.
  • 모델 · 가격표는 src/warehouse_lecture/config/llm.yaml, 호출 기록은 logs/openai_usage.jsonl에 있다.
  • source 없이 ros2를 치면 ros2: command not found 또는 패키지를 찾지 못한다. 터미널(탭)을 새로 열 때마다 다시 source한다.

3. 실행 구조 · 부스 · 설정 · 문제 해결

핵심 개념: 터미널 두 개

터미널역할명령
터미널 1launch 하나로 모든 프로세스 실행./scripts/robotworld start
터미널 2명령과 실습./scripts/robotworld <명령> (ros2를 직접 칠 때만 source scripts/env.sh)

source 안 한 터미널에서도 ./scripts/robotworld <명령>은 바로 쓸 수 있다. ros2 CLI는 exec ros2 ... 형식으로 실행한다.

실습 명령: wrapper와 launch 인자

./scripts/robotworld start      # 시뮬레이터 실행 (한 번에 하나만, lock 파일로 중복 차단)
./scripts/robotworld stop       # 종료 (남은 프로세스까지 정리)
./scripts/robotworld fms        # 웹 FMS → http://localhost:8080
./scripts/robotworld drive      # MoveIt · Nav2 없이 주행만
./scripts/robotworld display    # 로봇 모델(URDF)만 RViz2에 표시

start, drive, slam, moveit 뒤에 인자:=값 형식으로 인자를 붙인다. 기본값은 작업 공간 맨 위 sim_config.yaml(profile: high)이다.

명령줄 인자 (rviz:=false)>sim_config.yaml>profile 기본값 
cd ~/pinklab_robotworld2026
sed -i 's/^profile: high/profile: low/' sim_config.yaml     # 편집기로 고쳐도 같음
./scripts/robotworld start
./scripts/robotworld start profile:=high rviz:=false         # 명령줄 인자가 파일보다 우선
./scripts/robotworld start profile:=low       # 이번 실행만 low
./scripts/robotworld start viewer:=false      # MuJoCo 창 없이 RViz만
./scripts/robotworld start rviz:=false        # RViz 없이 MuJoCo 창만 (지도는 웹 FMS 로)

sim_config.yaml은 실행할 때마다 읽으므로 고친 뒤 빌드 없이 다시 실행하면 된다. 실행 첫머리 [sim_config] 줄에 실제로 적용된 값이 표시된다.

4. MuJoCo 소개와 뷰어 조작

핵심 개념

이름
Multi-Joint dynamics with Contact · 관절과 접촉을 푸는 물리 엔진
관리 · 라이선스
Google DeepMind가 관리하는 오픈소스 (Apache 2.0)
형태
프로그램이 아니라 라이브러리 · 내 Python 코드가 물리를 한 스텝씩 돌림

mujoco 패키지에는 로봇 모델이 없다. 공식 모델 모음 MuJoCo Menagerie를 따로 받는다. 로봇마다 폴더 하나이고, 그 안의 scene.xml을 연다.

흐름: 뷰어와 ROS 2의 관계

뷰어: 사람이 슬라이더로→data.ctrl←다음 장부터: ROS 2 노드가

실습 명령

# 터미널 1: 모델 받기
git clone --depth 1 https://github.com/google-deepmind/mujoco_menagerie.git ~/mujoco_menagerie
ls ~/mujoco_menagerie/unitree_go2

# 어떤 로봇이 있나 (폴더 하나 = 로봇 모델 하나)
ls -d ~/mujoco_menagerie/*/ | xargs -n1 basename | column -c 110

# 첫 번째 로봇: Franka Panda
cd ~/pinklab_robotworld2026
source scripts/env.sh
python -m mujoco.viewer --mjcf=$HOME/mujoco_menagerie/franka_emika_panda/scene.xml

# 두 번째 로봇: Unitree Go2
python -m mujoco.viewer --mjcf=$HOME/mujoco_menagerie/unitree_go2/scene.xml

ls -d .../*/는 폴더 이름만 나열하고, xargs -n1 basename은 경로 앞부분을 떼며, column -c 110은 폭 110 글자에 맞춰 여러 열로 정리한다.

영역역할

Franka Panda (로봇 팔)위치 액추에이터바로 물리가 돌며 서 있음 (Simulation의 Run이 켜진 상태)

확인 포인트

Go2가 주저앉는 것은 고장이 아니다. 토크를 넣어 주는 제어기가 없어서 받쳐 줄 힘이 없기 때문이다.
해 볼 것: Panda의 Control에서 actuator2 · actuator6을 움직여 어느 관절인지 확인한다. Go2를 Pause → Load key한 뒤 Control 슬라이더를 움직이고 Run해 다리 반응을 본다. 목록에서 다른 로봇(예: universal_robots_ur5e · unitree_h1)을 열어 본다.

5. 정리

핵심 정리

  • 물리는 MuJoCo, 로봇 소프트웨어는 ROS 2가 맡고, 자연어 지령부터 로봇 행동까지 한 워크스페이스에 있다.
  • 기준 환경은 Ubuntu 24.04 + ROS 2 Jazzy(native)이며 도커 · VM은 지원하지 않는다.
  • 설치는 ./scripts/install.sh, 점검은 ./scripts/robotworld doctor로 하고 ❌ 0건이면 준비 완료다.
  • numpy<2, opencv-python<4.11, setuptools<80 고정 버전은 올리지 않는다.
  • ./scripts/robotworld는 환경을 스스로 켠다. ros2를 직접 칠 때만 터미널마다 source scripts/env.sh를 한다 (ROS_DOMAIN_ID=44).
  • 실행 설정 우선순위는 명령줄 인자 > sim_config.yaml > profile 기본값이며, 느리면 profile:=low를 쓴다.
  • MuJoCo는 라이브러리이고 모델은 Menagerie에서 받는다. 뷰어에서는 사람이, 이후에는 ROS 2 노드가 data.ctrl을 채운다.

스스로 점검

  1. 새 터미널에서 ros2: command not found가 나왔다. 원인과 이 저장소에서 쓰는 해결 명령은 무엇인가?
  2. 시뮬레이터를 켠 상태에서 ./scripts/robotworld display를 쓰면 안 되는 이유는 무엇인가?
  3. Panda는 열어도 서 있는데 Go2는 주저앉는다. 액추에이터 종류로 설명해 보라.
