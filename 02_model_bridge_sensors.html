1. URDF 에서 MuJoCo 모델로 (04강)

핵심 개념

URDF 를 가진 ROS 2 사용자가 할 일은 세 단계입니다. ① 모델(URDF 를 MuJoCo 가 읽게 하고 빠진 것을 채움), ② 연결(브리지), ③ 확인. 이 절은 ①을 다룹니다. 예제는 lessons/01_mujoco_ros2/ 의 2링크 팔(two_link_arm.urdf)입니다.

① 모델→② 연결 (브리지)→③ 확인 (ROS 2 도구)
URDF 요소뜻예제 값
<link>강체 하나 · visual / collision / inertial 세 가지를 가짐link1: 원기둥 반지름 0.02, 길이 0.30 m, 질량 0.40, ixx = m(3r² + L²)/12 = 0.00304
<joint>두 링크의 관계 · parent / child 이름으로 트리를 만듦joint1: revolute, origin 0 0 0.06, axis 0 1 0, limit -1.57~1.57, effort 20, damping 0.5
fixed joint프레임만 만듦 · /joint_states 에 나오지 않음camera_joint(link2 위 0.26 m), camera_optical_joint(rpy 0 0 -1.5708)

camera_optical_frame 은 영상 좌표계(z = 보는 방향)이며 영상 메시지의 frame_id 가 됩니다. 내용이 없는 <link> 는 좌표계 이름만 필요한 링크입니다.

URDF 에 없는 것과 변환 스크립트

MuJoCo 는 mujoco.MjModel.from_xml_path() 로 URDF 를 바로 읽지만, 읽히는 것과 쓸 수 있는 것은 다릅니다. 그대로 읽으면 body 3 · actuator 0 · camera 0 이고, 1 초 돌리면 link1 이 base 원기둥과 충돌해 밀려나고(0.6 → 0.01 rad) link2 는 처져 관절 한계 2.0 rad 에서 멈춥니다. urdf_to_mjcf.py 의 build() 가 MjSpec 으로 빠진 것을 채웁니다.

단계build() 가 하는 일
1 읽기mujoco.MjSpec.from_file() 로 URDF 파싱 (MjSpec = 컴파일 전 모델)
2 물리 · 충돌timestep = 0.002 · collision geom 은 group 3(뷰어 기본 숨김) · add_exclude(base_link, link1) (없으면 0.24 rad 에서 멈춤)
3 세계light · floor · red_box · blue_box 를 worldbody 에 추가 (box size 는 반 길이)
4 카메라camera_optical_frame body 에 tip_camera, quat=[0, 1, 0, 0](x 축 180°), fovy 60
5 액추에이터관절마다 위치 액추에이터 <joint>_pos · ctrlrange = URDF limit · KP = {"joint1": 30.0, "joint2": 20.0}
6 컴파일spec.compile() → MjModel

URDF 안의 <mujoco><compiler fusestatic="false" discardvisual="false"/></mujoco> 태그는 MuJoCo 만 읽습니다. fixed 로 붙은 링크를 body 로 남기고, visual 모양도 geom 으로 남깁니다.

실습 명령

source scripts/env.sh
check_urdf lessons/01_mujoco_ros2/two_link_arm.urdf
ros2 launch lessons/01_mujoco_ros2/view_urdf.launch.py         # RViz + 관절 슬라이더
python lessons/01_mujoco_ros2/urdf_to_mjcf.py --raw            # 그대로 읽은 결과: body 3 · actuator 0 · camera 0
python lessons/01_mujoco_ros2/urdf_to_mjcf.py                  # 변환: body 6 · actuator 2 · camera 1
python -m mujoco.viewer --mjcf=lessons/01_mujoco_ros2/two_link_arm_from_urdf.xml

view_urdf.launch.py 는 robot_state_publisher(URDF + /joint_states → /tf · /robot_description), joint_state_publisher_gui, rviz2 세 노드를 띄웁니다. sim:=true 면 슬라이더 노드를 띄우지 않습니다.

확인 포인트

변환된 MJCF 에서 joint 의 origin 은 child body 의 pos 로 옮겨지고, cylinder size 는 반지름 · 반 길이(0.30 → 0.15)가 됩니다. 이름은 그대로 옮겨지므로 브리지와 ROS 2 가 같은 이름을 씁니다. 변환 결과 mass 1.17 kg 은 <inertial> 이 없는 base_link 를 모양 × 밀도 1000 으로 계산한 0.47 kg 을 포함합니다.
자주 막히는 곳. velocity 한계와 <mimic> 은 옮겨지지 않습니다. mimic 은 MJCF <equality><joint joint1="따라가는 관절" joint2="기준 관절" polycoef="offset multiplier 0 0 0"/> 로 직접 묶고, 액추에이터는 기준 관절에만 둡니다. mesh 는 package:// 를 풀지 않고 파일 이름만 남겨 meshdir 에서 찾으며, STL · OBJ 만 읽으므로 DAE 는 변환이 필요합니다.

2. MuJoCo 브리지: ROS 2 와 주고받기 (05강)

핵심 개념

Gazebo 에서 플러그인이 하던 일을 MuJoCo 에서는 브리지 노드 하나가 합니다. URDF 를 RViz 로 볼 때는 슬라이더가 /joint_states 를 내고, 시뮬레이터를 붙이면 브리지가 냅니다. robot_state_publisher · RViz · URDF 는 그대로입니다. 브리지는 저장된 XML 이 아니라 build() 를 직접 호출하므로 URDF 를 고치면 바로 반영됩니다.

MjModel
설계도. 변하지 않음.
MjData
상태. 스텝마다 변함. 쓰는 값은 data.ctrl 하나, 나머지는 읽는 값.
mj_step
한 번 = timestep 만큼 시간이 흐름. 1000 스텝 × 0.002 s = 2 초.

mujoco_basics.py 는 ROS 2 없이 data.ctrl[:] = [0.6, 1.5] 를 쓰고 mj_step 을 반복해 qpos 를 출력합니다. 이 루프에 ROS 2 를 끼우면 브리지가 됩니다(ctrl ← /cmd, qpos → /joint_states).

주고받는 토픽 (urdf_bridge.py)

방향토픽타입MuJoCo 쪽 값
나감/clockClockdata.time (매 스텝)
나감/joint_statesJointStateqpos · qvel · qfrc_actuator (50 Hz)
나감/tip_posePoseStampedxpos · xquat 를 base_link 기준으로 변환
나감/tip_camera/image_rawImagemujoco.Renderer 240×320 rgb8 (5 Hz)
들어옴/cmdFloat64MultiArraydata.ctrl (개수 · NaN 검사 후 ctrlrange 로 clip)

자세를 보내는 길은 둘입니다. 링크 TF 는 브리지가 관절 각만 내고 robot_state_publisher 가 URDF 로 계산합니다. 시뮬레이터만 아는 자세(주행 로봇의 위치 · 물체)는 브리지가 xpos · xquat 에서 직접 냅니다.

스텝 루프 (spin)

1. mj_step→2. /clock→3. /joint_states · /tip_pose→4. 카메라→5. spin_once(timeout_sec=0)→6. 벽시계 맞춰 sleep
  • 발행 주기는 시뮬레이션 시간 기준(t >= self.next_state)입니다.
  • /cmd 콜백은 spin_once 에서, 즉 항상 두 스텝 사이에 실행되며 목표만 씁니다. 팔을 움직이는 것은 다음 mj_step 입니다.
  • MuJoCo 쿼터니언은 [w, x, y, z] 배열이므로 메시지 필드 이름으로 대입합니다.

# 터미널 2: robot_state_publisher 와 RViz

확인 포인트

토픽 10 개, 브리지 노드 하나가 보이고 /joint_states 는 50 Hz, 영상은 5 Hz 입니다. [0.6, 1.5] 명령 뒤 joint1 은 0.640(kp 30 위치 제어가 중력에 밀린 처짐), effort -1.21 N·m 입니다. /tip_pose 와 tf2_echo 위치가 0.404 · 0.000 · 0.151 m 로 일치하면(쿼터니언 부호가 모두 반대인 것은 같은 회전) 변환 · 브리지 · URDF 가 서로 맞습니다.
팔이 수직이면 카메라가 하늘을 봐서 영상이 검은 것이 정상입니다. 값을 3 개 보내면({data: [0.6, 1.5, 0.1]}) 브리지가 /cmd ignored 경고를 냅니다. mj_step 을 부르지 않으면 세계가 멈춥니다(뷰어는 물리를 돌리지 않음).

3. 창고 로봇 모델: Xacro → MJCF (06강)

핵심 개념

창고 로봇은 OpenARM(오픈소스 양팔 매니퓰레이터)과 Vic Pinky(PinkLAB 차동 구동 모바일 베이스)를 조립한 것입니다. Xacro 를 한 번 펼친 URDF 문자열 하나가 세 곳(robot_state_publisher, MuJoCo 브리지, MoveIt)으로 가고, 이름이 그대로라서 서로 맞물립니다.

mobile_openarm.urdf.xacro→expand_urdf()→robot.urdf→build_model()→warehouse.xml→Physics · bridge
  • expand_urdf() 는 xacro.process_file 로 include · macro 를 펼치고, ros2_control 은 항상 "false" 입니다(관절 제어는 MuJoCo 브리지가 맡음).
  • warehouse.launch.py 는 시작할 때 한 번 펼쳐 artifacts/mobile_generated/robot.urdf 로 저장하고, 브리지는 별도 프로세스(ExecuteProcess, venv python)라 --urdf-file 경로로 받습니다. OnProcessExit 로 MuJoCo 쪽이 끝나면 launch 전체가 끝납니다.

4. Bringup · 센서 · TF (07강 전반)

핵심 개념

warehouse.launch.py 하나로 시뮬레이터를 띄웁니다. mode 인자는 drive · slam · nav 이고, ./scripts/robotworld wrapper 가 launch 인자를 대신 채웁니다. 브리지 프로세스는 bridge.py(ROS 2 노드) + model.py(Physics)로 이루어지며 루프는 100 Hz, 한 바퀴에 mj_step 5 회입니다.

5. 오도메트리 계산과 오차 (07강 후반)

핵심 개념

/odom 은 참값이 아니라 바퀴 회전으로 계산한 위치입니다. Physics.step() 이 차동 구동 기구학으로 명령을 바퀴 속도로 바꾸고, 스텝 전후 바퀴 각 차이로 자세를 적분합니다.

단계식 (model.py step)
가속 제한한 틱(dt = 5 × timestep = 0.01 s)에 바꿀 수 있는 속도를 clip → /cmd_vel 이 갑자기 바뀌어도 부드럽게
명령 → 바퀴좌 · 우 바퀴 각속도 = (v ∓ w × track / 2) / radius → data.ctrl
호 길이dl, dr = (스텝 후 바퀴 각 - 스텝 전) × radius
전진 · 회전ds = (dl + dr) / 2 · da = (dr - dl) / track
적분theta = yaw + da / 2 (중점 각도) · x += ds·cos(theta), y += ds·sin(theta), yaw += da

/odom 메시지와 공분산

frame_id odom, child_frame_id base_footprint 이며 pose 는 odom 프레임에서 본 위치, twist 는 로봇 기준 속도(linear.x, angular.z)입니다. 같은 값을 TF 로도 내며, 이것이 TF 트리에서 odom 과 로봇을 잇는 유일한 고리입니다.

분산pose 축twist 축의미 (표준편차)
0.0025x · yvx · vy± 5 cm · ± 0.05 m/s
1e6z · roll · pitchvz · ωx · ωy재지 않음 → 무시하라는 표시
0.01yawωz± 0.1 rad (약 6°) · ± 0.1 rad/s

손으로 정한 고정값이며 AMCL 은 사용하지 않고, robot_localization EKF 같은 센서 융합 노드가 사용합니다.

실험: /odom vs /ground_truth

프레임은 world · odom · base_footprint 셋입니다. docs/camp/odom_experiment.py 는 /cmd_vel 로 한 변 1 m 사각형을 주행(출발 (5.0, −3.7))하며 /odom 과 /ground_truth 를 함께 기록합니다. 직진은 odom 거리, 회전은 odom yaw 기준으로 끝냅니다.

주행거리위치 오차yaw 오차
1 바퀴약 4 m0.3 cm0.2°
3 바퀴약 12 m0.8 cm0.6°

오차는 회전 구간에서 생기고 직진에서는 거의 늘지 않으며, 줄지 않고 계속 누적됩니다. 시뮬레이터라 바퀴 미끄러짐이 없고 반지름과 윤거가 모델 값과 같아서 작습니다. 그래도 생기는 원인은 바퀴가 바닥에 살짝 파고듦, 제자리 회전에서 바퀴와 캐스터가 끌림, 접촉이 스프링이라는 점입니다. yaw 오차는 다음 직진에서 옆으로 벌어집니다.

실습 명령

ros2 topic echo --once /odom
ros2 run tf2_ros tf2_echo odom base_footprint
ros2 topic echo --once /ground_truth
python docs/camp/odom_experiment.py --side 1.0 --laps 1 --out artifacts/dev/odom_square1
python docs/camp/odom_experiment.py --side 1.0 --laps 3 --out artifacts/dev/odom_square3
# spawn 을 바꿔도 odom 은 0 에서 시작
./scripts/robotworld drive viewer:=false rviz:=false spawn:=drinks     # 터미널 1
ros2 topic echo --once /ground_truth                                   # 터미널 2
ros2 topic echo --once /odom

확인 포인트

spawn:=drinks 에서 로봇은 음료대 앞 (7.65, −2.82) 에 있지만 odom 값은 (0, 0, 0) 입니다. odom 은 출발점을 원점으로 삼을 뿐 지도 위 위치를 모르며, 이 빈칸은 SLAM · AMCL 이 map → odom 으로 채웁니다(3장).
/odom 과 /ground_truth 를 비교할 때는 같은 시각(같은 틱)의 값끼리 비교합니다. /cmd_vel 을 한 번만 보내면 0.5 s 뒤 정지합니다(command_timeout).

6. 정리

  • MuJoCo 는 URDF 를 바로 읽지만 물리 옵션 · 세계 · 카메라 · 액추에이터 · 충돌 제외 · mimic 은 변환 단계에서 직접 채워야 합니다.
  • URDF 의 링크 · 관절 이름이 MJCF 와 /joint_states 에 그대로 이어지므로 robot_state_publisher · 브리지 · MoveIt 이 같은 URDF 로 맞물립니다.
  • 브리지는 mj_step 루프에 토픽을 끼운 것입니다. /cmd → data.ctrl, qpos → /joint_states, data.time → /clock.
  • 링크 TF 는 robot_state_publisher 가, 시뮬레이터만 아는 자세(odom → base_footprint, /tip_pose)는 브리지가 냅니다.
  • 라이다는 mj_multiRay 로 광선 360 개를 쏘아 10 Hz best effort /scan 으로 냅니다.
  • /odom 은 바퀴 회전 적분값으로 출발점이 원점이며, 오차는 회전에서 생기고 계속 누적됩니다.
  • 두 경로(브리지 값과 TF 계산값, odom 과 ground_truth)를 비교해 모델 · 브리지 · URDF 가 맞는지 확인합니다.
